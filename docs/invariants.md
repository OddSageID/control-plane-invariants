# Core Invariants

Version: 0.1.0-draft

This document defines foundational invariants that any IEK-compliant system MUST satisfy. Domain-specific invariants are defined by instantiating systems.

---

## Notation

- **MUST**: Absolute requirement. Violation is a system defect.
- **MUST NOT**: Absolute prohibition. Violation is a system defect.
- **Invariant ID**: Stable identifier for reference in ImbalanceDescriptors.

---

## Ledger Invariants

### INV-L001: Append-Only Integrity

The Ledger MUST NOT permit modification or deletion of any event after it has been assigned a sequence_id.

**Rationale**: All derived state depends on event immutability.

**Violation Detection**: Hash chain verification; sequence gap detection.

---

### INV-L002: Monotonic Sequencing

Every event appended to the Ledger MUST receive a sequence_id strictly greater than all prior sequence_ids.

**Rationale**: Enables deterministic ordering and replay.

**Violation Detection**: Sequence_id comparison on append.

---

### INV-L003: Referential Integrity

If an event references prior sequence_ids (e.g., Revocation targets), those sequence_ids MUST exist in the Ledger.

**Rationale**: Prevents dangling references; ensures revocations target real events.

**Violation Detection**: Lookup on append; replay verification.

---

## Evaluator Invariants

### INV-E001: Determinism

Given identical inputs (DerivedState, Ruleset), an Evaluator MUST produce identical outputs.

**Rationale**: Enables reproducibility, testing, and audit replay.

**Violation Detection**: Repeated evaluation comparison; fuzzing.

---

### INV-E002: Read-Only Operation

An Evaluator MUST NOT write to the Ledger, modify Control Plane configuration, or produce side effects beyond its return value.

**Rationale**: Ensures evaluation is observation, not action.

**Violation Detection**: Capability restriction; sandbox enforcement.

---

## Resolver Invariants

### INV-R001: Subtractive Correction Only

A Resolver MUST NOT generate events that create new obligations, add state, or impose requirements beyond nullifying the effects of targeted events.

**Rationale**: Prevents scope creep from correction into coercion.

**Violation Detection**: Event type validation; semantic audit.

---

### INV-R002: Imbalance Reference Requirement

Every Revocation event generated by a Resolver MUST reference a specific ImbalanceDescriptor.

**Rationale**: Ensures traceability; prevents arbitrary revocations.

**Violation Detection**: Schema validation; referential check.

---

## Control Plane Invariants

### INV-C001: Configuration Versioning

Every active Ruleset MUST have an immutable version identifier. Changes to a Ruleset MUST produce a new version, not modify an existing one.

**Rationale**: Enables point-in-time audit; prevents retroactive rule changes.

**Violation Detection**: Version registry integrity check.
